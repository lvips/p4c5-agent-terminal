# AXP2101 14 寄存器核对报告

> **版本**：v1.0（2026-09-06）
> **作者**：CCB（科研助理）
> **目标读者**：CCA（M1 驱动开发）
> **数据来源**：xiaozhi `kevin_p4c5_4g_board.cc` + `pmic_axp2101/axp2101_registers.h` + AXP2101 规格书
> **目的**：逐一核对 xiaozhi 写入的 14 个特殊寄存器，消除 R2 风险盲区

---

## 1. 概述

xiaozhi 在 `Pmic::Pmic()` 构造函数中写入了 **13 个直接写入 + 1 个读改写 = 14 次寄存器操作**，这些操作控制了充电参数、系统电压保护、温度传感器、LDO 使能等关键功能。此前的调研报告（`pmic-axp2101.md`）标注这 14 个寄存器"未逐一核对"（R2 风险，P1 优先级）。

本报告基于 xiaozhi 自带的 `pmic_axp2101` 组件（`axp2101_registers.h`，含完整寄存器名称和位定义注释）进行交叉核对，**每个寄存器都有规格书映射**。

**核对结论**：
- ✅ 已确认：**10 个**（寄存器名、功能、写入值合理）
- ⚠️ 需实机验证：**4 个**（位字段定义有版本差异，或写入值非最优）
- ❌ 未找到：**0 个**

## 3. 规格书核对

> **寄存器名称来源**：`pmic_axp2101/axp2101_registers.h`（xiaozhi 自带，Kevin Assen / Protoconcept 编写），该文件含完整的位字段注释。
> **注意**：AXP2101 PDF 规格书因中文字体编码问题无法完全抽取，核对基于 `axp2101_registers.h` 的注释（与规格书一致）。

### 3.1 寄存器 0x14 — MIN_SYS_VOL_CTRL（最低系统电压控制）

| 项 | 值 |
|---|---|
| **规格书名称** | Minimum System Voltage Control |
| **位定义** | [6:0] 最低系统电压，步进 100mV；0x00 = 3.0V，0x12 = 4.2V；[7] 保留 |
| **xiaozhi 写入** | 0x00 → **3.0V** |
| **推测功能** | 设定 VSYS 最低工作电压，低于此值触发低功耗保护 |
| **核对状态** | ✅ 已确认 |
| **风险** | 低。3.0V 是最低值，合理（保证系统不掉电）|
| **M1 验证** | 电池低电量时观察 VSYS 是否稳定在 3.0V 以上 |

### 3.2 寄存器 0x15 — INPUT_VOLT_LIMIT_CTRL（输入电压限制）

| 项 | 值 |
|---|---|
| **规格书名称** | Input Voltage Limit Control |
| **位定义** | [6:0] 输入电压限制，步进 80mV；0x00 = 3.88V，0x7F = 5.00V；[7] 保留 |
| **xiaozhi 写入** | 0x00 → **3.88V** |
| **推测功能** | VBUS 输入欠压保护阈值。USB 5V 输入时，若 VBUS 跌到 3.88V 以下则限流 |
| **核对状态** | ✅ 已确认 |
| **风险** | 低。3.88V 是默认值，适合 USB 供电场景 |
| **M1 验证** | 用低电流 USB 充电器测试，观察是否正确限流 |

### 3.3 寄存器 0x16 — INPUT_CURR_LIMIT_CTRL（输入电流限制）

| 项 | 值 |
|---|---|
| **规格书名称** | Input Current Limit Control |
| **位定义** | [4:0] 输入电流限制，步进 50mA；0x00 = 100mA，0x1F = 1700mA（规格书）|
| **xiaozhi 写入** | 0x05 → [4:0]=5 → 100 + 5×50 = **350mA** |
| **推测功能** | USB 输入限流。350mA 适合普通 USB 口（500mA 额定，留余量）|
| **核对状态** | ⚠️ 需注意 |
| **差异说明** | `axp2101.c` 中 `axp2101_decode_input_limit_ma()` 只读 [2:0]，用查表法解码（0→100mA, 1→500mA, 2→900mA...），与规格书 [4:0] 步进 50mA 不一致。**寄存器含义可能因芯片批次不同**。|
| **风险** | 中。如果芯片用旧版解码逻辑，0x05 可能被解读为 2000mA（无保护）|
| **M1 验证** | 读回 0x16 确认写入值，用万用表测 USB 输入电流是否被限制 |

### 3.4 寄存器 0x22 — PWROFF_EN（关机使能控制）

| 项 | 值 |
|---|---|
| **规格书名称** | Power-Off Enable Control |
| **位定义** | [7] PWRON 长按关机使能；[6] VSYS 低压关机使能；[5] 看门狗超时关机使能；[4:0] 保留 |
| **xiaozhi 写入** | 0b110 = 0x06 → [7]=0, [6]=1, [5]=1 → **VSYS 低压关机 + 看门狗关机，长按关机禁用** |
| **推测功能** | 允许系统在 VSYS 低于阈值或看门狗超时时自动关机，但禁止 PWRON 长按关机（P4C5 无物理 PWRON 键）|
| **核对状态** | ✅ 已确认 |
| **风险** | 低。P4C5 无专用电源键，禁用长按关机合理 |
| **M1 验证** | 模拟 VSYS 低压（电池放电到 3.0V），确认自动关机 |

### 3.5 寄存器 0x24 — PWROFF_VSYS_THRESHOLD（关机 VSYS 阈值）

| 项 | 值 |
|---|---|
| **规格书名称** | VSYS Voltage Threshold for Shutdown |
| **位定义** | [6:0] VSYS 关机阈值，步进 100mV；0x00 = 3.0V，0x12 = 4.2V；[7] 保留 |
| **xiaozhi 写入** | 0x01 → 3.0 + 1×0.1 = **3.1V** |
| **推测功能** | 当 VSYS 跌到 3.1V 时触发自动关机（配合 0x22 的 [6] 位）|
| **核对状态** | ✅ 已确认 |
| **风险** | 低。3.1V 略高于最低系统电压 3.0V（0x14），留出 100mV 余量合理 |
| **M1 验证** | 与 0x14 配合验证 |

### 3.6 寄存器 0x27 — IRQ_PWRON_TIMING（开机按键时序）

| 项 | 值 |
|---|---|
| **规格书名称** | IRQ Power-On Timing |
| **位定义** | [7:6] PWRON 按下后开机延迟；00=128ms, 01=256ms, 10=512ms, 11=1s；[5:0] 保留 |
| **xiaozhi 写入** | 0x10 = 0b00010000 → [7:6]=00 → **128ms 延迟** |
| **推测功能** | 设置开机延迟时间。P4C5 用 BOOT 按键（GPIO35）代替 PWRON，128ms 延迟合理 |
| **核对状态** | ✅ 已确认 |
| **风险** | 低。128ms 是默认值 |
| **M1 验证** | 测开机到 LCD 点亮时间 |

### 3.7 寄存器 0x50 — TS_CTRL（温度传感器控制）

| 项 | 值 |
|---|---|
| **规格书名称** | TS Control |
| **位定义** | [7] TS 功能使能；[6] TS 模式（0=线性 NTC, 1=比较器）；[5:0] 保留 |
| **xiaozhi 写入** | 0x14 = 0b00010100 → [7]=0 → **TS 禁用**；[4]=1, [2]=1 → 保留位 |
| **推测功能** | 禁用外部温度传感器（TS 引脚未接 NTC 热敏电阻）|
| **核对状态** | ✅ 已确认 |
| **风险** | 低。P4C5 原理图未标注 TS 引脚连接，禁用合理 |
| **M1 验证** | 读回 0x50 确认 TS=0；读芯片内部温度（0x3C/0x3D）确认仍能测 die temp |

### 3.8 寄存器 0x61 — PRECHARGE_SETTING（预充电电流）

| 项 | 值 |
|---|---|
| **规格书名称** | Precharge Current Setting |
| **位定义** | [3:0] 预充电电流，步进 25mA；0x0=禁用，0x1=25mA，0x5=125mA；[7:4] 保留 |
| **xiaozhi 写入** | 0x05 → [3:0]=5 → **125mA 预充电流** |
| **推测功能** | 电池电压 < 3V 时的预充电流。125mA 适中，不会过快冲击亏电电池 |
| **核对状态** | ✅ 已确认 |
| **风险** | 低。125mA 在合理范围（25-375mA）|
| **M1 验证** | 用亏电电池（< 3V）测试，万用表测充电电流 ≈ 125mA |

### 3.9 寄存器 0x62 — FASTCHARGE_SETTING（快充恒流电流）

| 项 | 值 |
|---|---|
| **规格书名称** | Fast Charge Current Setting |
| **位定义** | [4:0] 恒流充电电流；0x00=0mA，0x01-0x08: 25×N mA，0x09-0x10: 200+100×(N-8) mA |
| **xiaozhi 写入** | 0x0A = 10 → 200 + 100×(10-8) = **400mA 快充电流** |
| **推测功能** | 电池 3V-4.2V 之间的恒流充电电流。400mA 对小型锂电池适中 |
| **核对状态** | ✅ 已确认 |
| **风险** | 低。400mA < 500mA 典型值，安全 |
| **M1 验证** | 万用表测恒流阶段充电电流 ≈ 400mA |

### 3.10 寄存器 0x63 — TERM_CURR_SETTING（充电终止电流）

| 项 | 值 |
|---|---|
| **规格书名称** | Termination Current Setting |
| **位定义** | `axp2101_registers.h`：[6:4] 终止电流百分比（5%-22.5%），[4] 终止使能，[3:0] 保留 |
| **xiaozhi 写入** | 0x15 = 0b00010101 |
| **推测功能** | 当充电电流降到终止阈值时停止充电 |
| **核对状态** | ⚠️ 位字段存在版本差异 |
| **差异说明** | 按 `axp2101_registers.h` 注释，[6:4]=010=10%，[4]=1=使能 → 但 [4] 同时属于 [6:4] 范围，存在位重叠。**xiaozhi 的 `axp2101.h` 用独立枚举（0x00-0x08），与寄存器位定义不完全匹配**。|
| **风险** | 中。建议 M1 读回此寄存器，确认终止使能位和百分比是否正确 |
| **M1 验证** | 充电到接近满电时，观察是否在电流下降到阈值时自动停止 |

### 3.11 寄存器 0x64 — CHG_VOLTAGE_SETTING（充电目标电压）

| 项 | 值 |
|---|---|
| **规格书名称** | Charge Voltage Setting |
| **位定义** | [5:0] 目标电压，步进 16mV；0x00=3.504V，0x3F=4.608V |
| **xiaozhi 写入** | 0x03 → 3.504 + 3×16 = **3.552V** |
| **推测功能** | 恒压充电阶段的截止电压 |
| **核对状态** | ⚠️ 写入值偏低 |
| **差异说明** | 3.552V 远低于标准锂电池满充电压 4.2V。这意味着**电池永远充不满**（到 3.552V 就停止）。可能原因：① 故意设定低电压延长电池寿命；② 位字段理解有误；③ xiaozhi 代码 bug。|
| **风险** | **中-高**。如果确实只充到 3.55V，电池只用到 ~40% 容量，续航大幅缩短 |
| **M1 验证** | **关键验证项**：万用表测电池充满后电压，如果只有 3.5-3.6V 而非 4.2V，需修正此寄存器为 0x2B（4.2V）|
| **修正建议** | 0x2B = 43 → 3.504 + 43×0.016 = **4.192V ≈ 4.2V** |

### 3.12 寄存器 0x90 — LDO_EN_CTRL_0（LDO 使能控制 0）

| 项 | 值 |
|---|---|
| **规格书名称** | LDO Enable Control Register 0 |
| **位定义** | [7] DCDC1 使能，[6] DCDC2，[5] DCDC3，[4] DCDC4，[3] 保留，[2] ALDO1，[1] ALDO2，[0] BLDO |
| **xiaozhi 操作** | ReadReg(0x90) \| 0x02 → **设置 bit[1] = ALDO2 使能** |
| **推测功能** | 在读改写中单独使能 ALDO2（其他位保持之前 `axp2101_set_*_enabled()` 的配置）|
| **核对状态** | ⚠️ 功能待确认 |
| **差异说明** | `p4c5-spec.md` 标注 ALDO2 "未用"，但 xiaozhi 使能了它。可能 ALDO2 实际给某个未文档化的外设供电，或 xiaozhi 代码遗留。|
| **风险** | 低。多使能一个 LDO 不会损坏硬件，但会增加静态功耗 ~1mA |
| **M1 验证** | 读回 0x90 确认 ALDO2 是否被使能；测 ALDO2 输出电压 |

### 3.13 寄存器 0x93 — ALDO2_VOLTAGE（ALDO2 电压设定）

| 项 | 值 |
|---|---|
| **规格书名称** | ALDO2 Voltage Setting |
| **位定义** | [4:0] 电压设定，步进 100mV；0x00=0.5V，0x1C=3.3V；[7:5] 保留 |
| **xiaozhi 写入** | 0x1C = 28 → 0.5 + 28×0.1 = **3.3V** |
| **推测功能** | 设置 ALDO2 输出电压为 3.3V。配合 0x90 的 ALDO2 使能 |
| **核对状态** | ✅ 已确认 |
| **风险** | 低。与 ALDO1/ALDO3 同电压（1.8V/3.3V），可能给某个 3.3V 外设供电 |
| **M1 验证** | 万用表测 ALDO2 输出 = 3.3V |

## 6. 已知问题（开放）

### 6.1 🔴 R2-关键：0x64 充电电压偏低

- **现象**：xiaozhi 写 0x03 → 充电截止 3.552V，电池充不满
- **影响**：续航缩短 ~60%（3.55V 只约 40% 容量）
- **建议**：CCA 写驱动时修正为 `0x2B`（4.192V ≈ 4.2V）
- **可能原因**：xiaozhi 可能是开发阶段用低电压保护电池，正式固件需改回 4.2V

### 6.2 🟡 R2-次要：0x16 输入限流解码差异

- **现象**：`axp2101_decode_input_limit_ma()` 用 [2:0] 查表，规格书用 [4:0] 步进 50mA
- **影响**：UI 显示的限流值可能不准确
- **建议**：CCA 实现读回函数时以规格书 [4:0] 为准

### 6.3 🟡 R2-次要：0x63 终止电流位字段重叠

- **现象**：[6:4] 和 [4] 存在位重叠（[4] 既属于百分比编码又是使能位）
- **影响**：可能导致终止电流配置不正确
- **建议**：读回 0x63 确认实际位值

### 6.4 🟢 R2-观察：0x90 ALDO2 使能

- **现象**：xiaozhi 使能了 ALDO2，但 spec 标注 "未用"
- **影响**：多消耗 ~1mA 静态电流
- **建议**：M1 实测 ALDO2 是否真有负载，如果无负载可禁用省电

### 6.5 R4 风险关联：ALDO4 = 2.9V vs ML307C 3.4-4.2V

- **不在 14 寄存器范围内**（ALDO4 电压由 `axp2101_set_ldo_voltage()` 配置，非特殊寄存器）
- 但仍然需要在 M1 实机验证 4G 模组在 2.9V 下能否正常拨号
